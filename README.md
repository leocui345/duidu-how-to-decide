# duidu-how-to-decide

> 把安妮·杜克《How to Decide》（中译名《对赌·实践版》，中信 2022）蒸馏成一组**可被 Agent 精准调用**的决策能力。
> 不是书摘，不是术语表——是 16 张原子能力卡 + 7 个独立触发 Skill + 1 个来源路由入口。
> 可以帮你在现代生活中遇到信息不对称事件时优化你的决策。

**状态**：8 个技能入口 / 16 张能力卡 ｜ 触发评测**尚未执行**（见下文「状态与诚实边界」）｜ 仅供个人学习与内部使用

---

## 这是什么

一本方法论密集的书，如果只做成"一本可检索的电子书"，会遇到一个具体问题：**单个 Skill 的 description 要覆盖全书几十个意图，触发必然模糊。**

这个仓库的做法是把它拆开：

| 层级 | 数量 | 作用 |
|---|---|---|
| **独立 Skill** | 7 | 高频、各自能被单独说出的意图——精准触发 |
| **来源路由入口** | 1 | 承载复盘等"说不清属于哪类"的问题 + 全部 16 张能力卡 |
| **能力卡** | 16 | 原子方法论单元，RIA++ 六段结构 |

**可发现入口总数 8 个**（软预算 8，压线）。未晋级的 9 张卡**一张没删**，全部经路由入口可达。

## 8 个能力

| Skill | 什么时候会被唤起 | 一句话 |
|---|---|---|
| `six-step-decision` | 我该不该做 X / 各有各的好定不下来 | 穷举结果 → 标回报大小 → 标概率 → 换算成同一单位比较 |
| `premortem-backcast` | 帮我想想会怎么失败 / 帮我排雷 | 假想已经失败，可控与不可控原因各列 5 条并标概率 |
| `decision-speed-triage` | 这事值不值得纠结 / 两个都差不多选不出来 | 按"决策不正确的代价"分配时间 |
| `probability-externalization` | "大概率"到底是多少 / 这判断靠谱吗 | 换成百分比 → 给范围 → 震惊测验（十发九中） |
| `decision-hygiene` | 团队开会没人提反对意见 / 怎么问才不被带偏 | 隔离观点与结果；先单独、后匿名、再讨论 |
| `asymmetric-bets` | 要不要试一下 / "就这一次" | 先问不对称性，再问累积性 |
| `voluntary-quitting` | 都投入这么多了要不要止损 | 剥离沉没成本 → 算退出成本 → 反事实提问 |
| `duidu-how-to-decide-router` | 复盘 / 后悔 / 我早该知道 / 上述之外的决策问题 | 路由入口，承载全部 16 张卡 |

16 张能力卡：上述 7 个 + `resulting-and-2x2`、`hindsight-and-tracker`、`multiple-possibilities`、`outside-view`、`sheep-in-wolfs-clothing`、`precommitment`、`tilt`、`hedging`、`decisions-as-portfolio`。

# 2. 复制 8 个入口到技能目录（名字不要改，见下）
cp -R duidu-how-to-decide/skills/* ~/.workbuddy/skills/

> ⚠️ **铁律：技能目录名必须等于其 `SKILL.md` 里 frontmatter 的 `name`。**

## 能力卡结构（RIA++）

每张卡统一六段，这是"给 agent 执行者蒸馏"而非"给人读书"的关键：

| 段 | 内容 | 为什么需要 |
|---|---|---|
| **R** | ≤150 字原文引用 + 精确页码 | 可追溯到原书，避免二手失真 |
| **I** | 用自己的话重写方法论骨架 | 检验是否真懂，而非抄书 |
| **A1** | 作者在书中亲自用过的案例 | 给 agent 可类比的真实素材 |
| **A2** | 触发情境 + **可识别的语言信号** + 与相邻能力的区分 | **决定 skill 是否真会被用起来** |
| **E** | 1-2-3 步骤，每步有**可判断的完成标准**与**判停点** | 防止"自由发挥" |
| **B** | 反场景 + 作者警告的失败模式 + **作者自身的局限** | 防止乱调用、帮倒忙 |

## 边界（重要）

**这个 Skill 不覆盖：**

- ❌ 投融资"对赌协议"（VAM / 估值调整机制）——**完全不同的东西**，书名撞车而已
- ❌ 赌博、赌球、押注策略
- ❌ 股票/基金推荐与投资建议
- ❌ 法律、医疗、税务的专业意见
- ❌ 《Thinking in Bets》的内容（那是杜克的另一本书）

**它也不做：** 替用户下结论。工具负责把问题拆清楚，选择权始终在用户手里。

---

## 三个值得记的设计取舍

1. **触发不可分的能力不硬拆。** 复盘三件套（结果导向 / 后视偏差 / 多重可能性）五项晋级判据全过，但用户一句"帮我复盘"会**三重触发**。拆成三个 Skill 只会制造混乱——交由路由入口按序加载。

2. **13 个通用术语被主动降级。** 光环效应、框架效应、羊群效应、沉没成本谬误……这些是心理学常识，模型本身就知道，**不满足"独特性"检验**。降级为术语表与边界引用，不占入口。淘汰它们不是损失——它们**占着入口预算、还稀释触发精度**。

3. **作者局限写进了边界段。** 例如"扑克是高频率可量化领域，平移到低频人生决策时有效性下降"、"好决策必然提高好结果比例**未被证明**"——都写进了对应能力的 B 段，而不是藏在 README 里。

## 它是怎么做出来的

由 `cangjie-skill` 的 **RIA-TV++** 流水线从零蒸馏产出，五个阶段：

```
阶段 0  Adler 整书理解（含 7 类作者局限批判）
阶段 1  5 路并行提取 → 44 个候选单元
阶段 1.5 三重验证（跨域/预测力/独特性）→ 合并为 16 个原子单元
阶段 1.6 晋级门（五判据 + 触发可分性 + 入口预算 ≤ 8）→ 7 promoted + 1 router
阶段 2-5 RIA++ 能力卡 → Zettelkasten 链接 → 压力测试 → 编译打包
```

关键做法：**内容不手写 SKILL.md**，而是写进一份 Capability Bundle，由编译器确定性产出。
改内容应改 Bundle 后重新编译，不要直接改已安装的产物。
