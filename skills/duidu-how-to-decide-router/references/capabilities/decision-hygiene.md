# 决策卫生

## R — Reading（原文）

> 别人发现他们与你意见相左的唯一途径，就是先知道你的观点。征求反馈时不要说出自己的观点。
>
> —— 第九章 286（小结要点）

> 真正对清单负责，就是要在别人无法提供高质量反馈所需的必要信息时懂得拒绝——这不是刻薄，而是善良。
>
> —— 第九章 283

## I — Interpretation（自述）

作者把医学的"卫生"概念迁移到**信息流**上：正如手术前要消毒，向别人征求反馈前也要"消毒"——否则你传给对方的是**被自己污染过的信息**。

观点和结果都具有**传染性**：
- 你先说想法 → 对方倾向附和（阿希实验中 **36.8%** 的人附和了明显错误的群体答案）；
- 你透露结果 → 对方屈从于结果导向与后视偏差。

更隐蔽的是**地位传染**：地位高的人（领导、专家、能说会道者）的意见传染性最强，而地位低的人即使掌握关键信息也不会开口（斯塔瑟&泰特斯实验：部分信息组几乎总是选错，尽管他们集体掌握着选出最优候选人的全部信息）。

作者给的处方是**流程层面的**：
1. **隔离观点**——先问、后说；
2. **隔离结果**——复盘旧决策时不要"剧透"结局；
3. **中立提问**——"你觉得凯文怎么样"不等于"你觉得凯文是个大浑蛋吗"；
4. **先单独、后匿名、再讨论**——团队三件套；
5. **清单负责**——反馈方信息不足时应当**拒绝作答**（这是全书最反直觉的一条）。

## A1 — Past Application（书中案例）

**斯塔瑟与泰特斯"学生会主席"实验（第九章 272–273）**
遇到问题：四人团队要从三名候选人中选出最合适的。
怎么用：部分信息组的每位成员只拿到不完整档案，其余信息分散在他人手里（且被告知可能不完整）。
结论：**他们几乎总是选错**——共识一旦形成，持异见者就不再发声。"即使他们握有判断候选人 A 最适合的全部信息，他们也不会分享。"

**扑克教练的拒答（第九章 283）**
遇到问题：学生问"最后一张牌该不该跟注"，但忘了说奖金数目。
怎么用：作者**拒绝回答**——"在奖金数目不明的情况下，我的意见既没有价值，也没有意义"。
结论：学生从此留意奖金数目。拒绝反而促成了学习。

## A2 — Future Trigger（何时触发）★

**适用情境（3–5 条）**：
1. 团队决策"没人提反对意见"，或"每次都是同一个人定调"；
2. 用户说"我问了一圈，大家都说好"（可能是回声室）；
3. 用户要**复盘一个已发生**的决策并征求他人意见；
4. 用户要向别人请教，但不确定怎么问才好；
5. 有人来征求你的反馈，但信息给得不全。

**语言信号（中/英）**：
"开会没人反对 / 大家好像都同意 / 我该问谁 / 怎么问才不会被带偏 / 我想听听别人的意见"
"no one disagrees / everyone agrees / how should I ask / get unbiased feedback / second opinion"

**与相邻能力的区分**：
- 与 **事前验尸与倒推**：本能力是**流程规范**（怎么收集意见）；事前验尸是**具体内容工具**（收集什么意见）。事前验尸的团队版**必须**遵守本能力的"先独立后汇总"。
- 与 **六步决策法**：六步法是个人决策流程，本能力管**多人信息流**。
- 与路由入口内的 **外视角与基准数**：那是"你个人怎么跳出去看"；本能力是"组织怎么防止互相污染"。

## E — Execution（可执行步骤）

1. **判定场景**：是"个人向他人请教"还是"团队集体决策"？
   完成标准：明确走哪条分支。
2. **（个人）先隔离**：告诉用户——问的时候**先别说自己的想法，也别提结果**。
   完成标准：用户能复述出"先问、后说"。
3. **（个人）中立提问**：把"你觉得 X 是不是很糟"改写成"你觉得 X 怎么样"。
   完成标准：问题里不含预设结论。
4. **（个人）列清单**：在问之前，先写下"对方要给出高质量反馈，需要知道哪些信息"（目标、价值取向、相关资源、具体情况）。
   完成标准：清单至少 4 项，且用户承诺提供。
5. **（团队）三件套**：会前**单独**收意见 → **匿名**分发给全体 → 再讨论。
   完成标准：讨论开始前，每个人都已经写下过独立意见。
6. **（团队）权宜版**：时间紧张时用"写纸条 + 一人朗读"，或"**按资历由浅到深**依次宣读"。
   完成标准：资历最浅的人先发言。
7. **（双方）清单负责**：若对方给不出必要信息 → **拒绝作答**，并说明缺什么。
   完成标准：拒绝时附上"我需要知道 X 才能给建议"。

**判停点**：
- 若用户问的是**完全不需要他人**的决策（如个人偏好），停止，本能力不适用。
- 若用户已明确说"我只是想要个安慰"，停止，不要硬推流程。

## B — Boundary（边界）

**不要使用的场景**：
- 时间紧迫的应急决策（走权宜版或直接决断）；
- 用户只想倾诉、不想要流程建议；
- 单人决策且不涉及他人反馈时（用六步法或事前验尸）。

**书中警告的失败模式**：
- **在别人给出反馈前先说自己的看法**——大幅增加附和概率；
- **向他人复盘时透露结果**——破坏反馈质量；
- **带诱导的提问方式**——已污染答案；
- **团队一起开会才提意见**——集体思维一旦形成，异见消失；
- **反馈方信息不足仍给建议**——建议既无价值也误导。

**作者局限带来的边界**：
- **未考虑强等级文化**（阶段 0 批判）：在东亚企业里，"资历最浅的先发言"可能让新人压力极大。落地时需加一层保护（先书面匿名，再口头）。
- **假定团队有流程自主权**：很多组织的会议形式由上级规定。此时只能建议"会前单独发邮件/消息收集"，不动会议本身。
- **"拒绝给建议"在人情社会有社交代价**：作者称之为"善良"，但在讲究面子的关系里可能显得傲慢。建议柔化措辞（"我想帮你，但缺这条信息我给的建议可能害你"）。

**易混淆的相邻方法**：回声室效应（是机制，本能力是解法）、光环效应（是机制）、事前验尸（是团队版的具体工具）。
